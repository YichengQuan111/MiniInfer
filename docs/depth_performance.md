# V1.6 深度推理性能基线

2026-10-11，本机九组案例、每组三次测量全部通过，共 **6,732 次成功请求**（含首请求和预热），Busy / Closed / Failure / Timeout 均为零。三个 TCP 服务在 318 / 963 / 963 次请求后正常排空，最终网络和 SDK 在途及预留字节均为零。[完整 suite](validation/v16_baseline/suite.json)、[数值汇总](validation/v16_baseline_summary.json)和每组 `measurements/repeat_*/raw.csv`、`memory.csv` 保留原始证据。

本机 TensorRT 的延迟明显低于 ORT CPU；混合 FP16 相对 FP32 有小幅收益。完整 SDK/TCP 路径的收益比 raw 路径有限，部分重复区间重叠。本报告不把单图、并发 1 的结果解释为通用吞吐承诺，也没有纳入未通过精度验收的首版 FP16。

## 固定条件与测量边界

- 硬件：i9-13980HX，WSL 可见 32 个逻辑 CPU；RTX 4080 Laptop，12,282 MiB，驱动 617.14。系统 WSL Ubuntu 24.04，GCC 13.3、CMake 3.28，Release C++17；ORT 1.21.0、TensorRT 10.8.0.43、CUDA runtime 12.4。
- 负载：Depth Anything V2 Small，B=1、518 静态输入；固定 `indoor_1` RGB8 图 1024×683，重复同一请求，输出 699,392 个 FP32 值。原图、模型、包、二进制哈希全部在 suite 中。
- ORT 4 线程；GPU 1 槽位；调用并发 1；SDK 等待队列 4、请求预算 128 MiB。TCP 为 1 连接线程，等待连接 4，网络请求上限 4、预算 128 MiB，收发超时 30 秒。
- 每次先测 1 个首请求，再预热，再测稳态。ORT 每次预热 5 / 稳态 100；TRT 20 / 300；每例重复 3 次。九例串行执行，期间不并行执行本任务的构建或测试。未锁定 GPU 频率、功率或其他桌面进程。
- raw：预处理完成后开始计时，返回拥有型 518×518 raw 输出；SDK：从 RGB 输入到拥有型原尺寸深度，含接纳、复制、前后处理；TCP：持久连接，含编码/收发/解码和验证。图像文件解码在稳态测量外。

以下区间为**三次独立统计的最小值—最大值**，没有平均分位数，也没有合并请求后重新计算分位数。P50/P95/P99 只含成功的稳态请求，采用线性插值；吞吐分母含整个稳态循环及失败尝试、CSV 写入和结果销毁。各完整报告与方法见 [基线方法](depth_benchmark_method.md)。不同进程测量的差值不直接解释为某组件的精确耗时。

## 引擎构建、进程启动与首请求

性能基线使用 V1.3 已验收的原模型包：FP32 engine SHA 前缀 `eb9fbd41e015`，混合 FP16 `d1ad5d6ec555`，完整哈希在 suite。原 engine 构建耗时分别为 **15.608645 s / 151.955208 s**；V1.6 从相同 ONNX 重新构建并复验的耗时为 **15.908249 s / 118.324933 s**。这里仅计 `buildSerializedNetwork`，不含前置 ONNX 解析和后续文件写入；重建工件不混入本次性能配置。

`main→ready` 包含参数、图像读取和本地模型初始化；进程启动→ready 额外包含进程创建、动态库加载和 stdout 接收延迟。新进程不意味着清空文件缓存；SDK 的包哈希检查包含在启动内。本次从 Windows 挂载目录读取模型，数字只代表记录的存储环境。

## 内存观测

RSS 每约 20 ms 读取 `/proc/PID/status`；显存每约 200 ms 读取 `nvidia-smi` 的**设备 0 总已用 MiB**，包括桌面及背景进程，不是模型进程分配量。短阶段可能漏采，缺失值在 JSON 中为 null，采样峰值不能视为瞬时峰值上界。相位按 stdout 接收时间划分，边界可能受调度延迟影响。

raw/SDK 的请求测量进程列包含该进程启动至退出；TCP 服务端列只覆盖客户端运行期间，真正服务器启动阶段另见上表。TCP 客户端自身 RSS 峰值分别为 ORT 178.86–178.90、TRT FP32 178.88–238.70、混合 FP16 178.86–178.88 MiB；不得拿客户端 RSS 作为服务模型内存。每次重复的 startup / first / warmup / steady / teardown 采样数与峰值均在原始报告中。

128 MiB 是每层请求接纳的预留预算，排除固定模型、后端 arena、CUDA context 和交付给调用者的结果，不是 RSS 或 GPU 内存限制。本次不据设备总显存的几 MiB 差异宣称 FP16 显存节省，也不将一次未采到的峰值写成零。

## 复现与范围

运行 [部署说明](depth_deployment.md) 中的全新构建、安装、引擎重建与 `run_depth_suite.py` 命令。脚本要求新输出目录，原始报告与失败计数一并保留；`all_runs_valid` 只说明测量格式有效，而 suite `passed` 还要求请求全部成功和服务器排空。

这是单图、固定形状、并发 1 的有限基线。100/300 样本的 P99 是本次样本分位数，不是尾延迟保证；没有测多客户端饱和吞吐、持续过载、30 分钟长稳或 ARM/Jetson 时延。以上属于 V2/E1 范围。精度依据另见 [精度报告](depth_accuracy.md)，本报告不能替代数值和任务效果验收。
